# 第 33 章：为什么需要地址、指针和引用？

我们希望函数直接更新一笔订单的金额，而不是只返回一个与原订单无关的新数。数据在内存中，调用者和函数怎样找到同一份对象？

## 整数绑定的变化只影响函数内部的 x 名字

整数绑定的变化只影响函数内部的 `x` 名字，外部 `amount` 仍然绑定 100。这个结果并不表示 Python “全部按值复制对象”传参，而是名字绑定语义。

**教学实现：**

```python
amount = 100
def change(x):
    x = 200
change(amount)
print(amount)  # 100
```

## 这次函数修改的是调用者和被调函数共同引用的字典对象

这次函数修改的是调用者和被调函数共同引用的字典对象。两个例子的差别迫使我们区分“修改局部绑定”和“通过一个别名修改共享对象”。

**用于触发限制的代码／输入（实验场景，不伪称来自框架）：**

```python
order = {"amount": 100}
def change(order):
    order["amount"] = 200
change(order)
print(order["amount"])  # 200
```

**因此需要的能力。** 理解如何间接找到同一份数据：地址、指针、引用以及别名语义。高级语言可以隐藏地址表示，但不会让共享可变性的逻辑问题消失。

## 把新机制落实成代码

**改进后的教学实现：**

```c
#include <stdio.h>
void change(long *amount) { *amount = 200; }
int main(void) {
    long amount = 100;
    change(&amount);
    printf("%ld\n", amount);  // 200
}
```

C 的 `&amount` 取得地址，`long *` 表示指向该类型对象的指针，`*amount` 在函数中通过指针访问并写入原存储位置。写法比 Python 显式，但共享存储这个事实更容易看见。

## 主函数中某个存储位置保存 100

主函数中某个存储位置保存 100；`change(&amount)` 将该位置地址交给被调函数；被调函数对地址解引用并写 200；返回后主函数再次读取该位置得到 200。

## Rust 通过可变借用表达当前调用要写入原数据的意图

Rust 通过可变借用表达当前调用要写入原数据的意图。

**Rust 示例（教学代码，非所引用仓库的源码节选）：**

```rust
fn change(amount: &mut i64) { *amount = 200; }
let mut amount = 100;
change(&mut amount);
assert_eq!(amount, 200);
```

Rust 的 `&mut` 不只是 C 式指针语法：安全代码受借用规则约束，不能把两者视为完全等价。

## 地址能够找到数据，也可能找到过期的数据

C 函数想原地修改调用者的订单合计，可以接收指针：

```c
#include <stdint.h>
void add(int64_t *total, int64_t x) {
    if (x >= 0) *total += x;
}
```

调用 `add(&total, 100)` 时，`&total` 得到对象地址，`*total` 通过该地址访问对象。这里多出的能力不是“高性能”，而是让被调用者操作调用者已经存在的存储。

相同能力也引入风险：地址可能是空的、越界的、悬垂的，或与其他可变访问形成冲突。C 的类型系统不能自动保证所有指针一直有效；Rust 通过引用与借用约束大幅限制安全代码中的此类行为。

请区分**地址**、**引用**、**拥有对象**：手里有一个地址，不等于这块数据由你释放，也不意味着你随时可以修改。这条边界是下一章生命周期问题的入口。

## 对照规范和真实实现

**源码/规范阅读路线（供读者核对，并非声称已经逐行验证）：** [Rust Reference：References、Borrowing](https://doc.rust-lang.org/reference/)。

核对 Rust 可变引用的访问限制，再用 C 标准相关参考比较地址与指针。规范禁止的行为与某个程序碰巧运行成功是两回事。

## 实验：写一个 C 函数接收 long 而不是 long*

写一个 C 函数接收 `long` 而不是 `long*`，在内部赋值 200；和指针版本对照主函数看到的值。

**应当观察到（自行运行前属于预期）：** 按值参数仅改变局部副本；指针允许访问原对象。复杂对象、引用与语言参数语义还会引出更精细的区别。

## 边界：间接访问可避免数据复制

间接访问可避免数据复制，也使多个地方可能修改同一状态。无效地址、生命周期结束或并发访问都是后续必须解决的边界。

**跨语言迁移时，** Python 对象引用、Java 对象引用、C 指针、C++ 引用、Rust 借用、Go 指针、Zig 指针都在表达间接访问，但安全保证不同。
