# 第 67 章：为什么大型代码库需要独立构建和版本管理？

订单程序使用两个第三方库。团队成员 A 的机器能跑，B 的机器却因为库版本不同产生行为差异。

## 探索性代码快速安装依赖十分方便

探索性代码快速安装依赖十分方便，只有自己本机运行时版本偏差未必明显。

**教学实现：**

```bash
# 简单原型，直接安装最新版依赖
# pip install some-package
# 下一周可能解析到不同版本
```

## 源码只是构建输入的一部分

源码只是构建输入的一部分，工具链版本、依赖版本、目标平台也影响最终行为。若这些输入不可追踪，复现故障就会变困难。

**用于触发限制的代码／输入（实验场景，不伪称来自框架）：**

```text
开发机依赖 A@1.0，CI 依赖 A@2.0。
同一订单输入在不同环境调用到不同 API。
失败不是业务算法变化，而是构建输入不一致。
```

**因此需要的能力。** 让构建依赖图与版本选择受控：声明直接依赖、锁定解析结果、记录工具链和环境，形成可重复的构建过程。

## 把新机制落实成代码

**改进后的教学实现：**

```text
教学构建清单（概念示意，不是某工具的真实锁文件）：
应用：order-service
语言运行时：Python 3.13
直接依赖：billing-lib@1.4
解析锁定：billing-lib@1.4.2 + 校验信息
目标环境：linux-x86_64
```

锁文件和依赖声明承担不同职责：声明允许范围，锁定实际解析版本。上面的文本仅说明所需信息，不伪装成 `uv.lock`、`go.sum` 或 Cargo.lock 语法。

## 开发者提交源码与锁定信息

开发者提交源码与锁定信息；CI 用指定工具链解析同一依赖图；构建产物可关联到输入版本。即使依赖相同，操作系统与环境变量仍可能影响运行结果。

## Rust Cargo 使用 Cargo.toml 描述包

Rust Cargo 使用 Cargo.toml 描述包，Cargo.lock 记录解析到的版本。

**TOML 示例（教学代码，非所引用仓库的源码节选）：**

```toml
[package]
name = "orders"
version = "0.1.0"
edition = "2021"

[dependencies]
# 此处按实际需要添加库与版本
```

这是真实 Cargo.toml 语法形状，锁文件应由 Cargo 生成，不应该人工编造。Java Maven/Gradle、Go modules、Python 包工具以及 Zig 构建各有不同约定。

## 本地能跑，为什么 CI 机器构建失败

同一订单项目在开发者机器上成功运行，但新机器缺少依赖包或使用不同版本的编译器。只保留源文件不足以稳定复现程序；构建还取决于依赖图、版本约束、目标平台和命令。

Python 常使用 `pyproject.toml` 与锁文件工具；Java 有 Maven/Gradle；Rust 使用 Cargo；Go Modules、Zig build、C/C++ 的 CMake 等承担不同程度的依赖与构建工作。它们不是完全相同的包格式，但都要回答**哪些源文件及依赖共同构成这次构建**。

实验：创建一个没有第三方依赖的最小函数，再添加一个测试依赖，在干净环境里执行安装和测试。记录语言版本、依赖版本和命令。不要只提交 README 中的“在我电脑能运行”。

构建可复现仍不同于运行可复现：当前时间、网络服务、CPU 架构和随机输入都可能改变运行行为。

## 对照规范和真实实现

**源码/规范阅读路线（供读者核对，并非声称已经逐行验证）：** [Rust/Cargo 官方源码与手册入口](https://github.com/rust-lang/rust)。

查 Cargo 版本解析与 lockfile 文档；同时记录本机 `python --version`、`go version` 等工具链信息，避免“我用的是最新版”这种不可复现描述。

## 实验：将同一依赖的两个版本放进隔离环境

将同一依赖的两个版本放进隔离环境，运行同一 API 测试并记录版本；不需要真的使用第三方支付库，选择纯计算小库即可。

**应当观察到（自行运行前属于预期）：** 当版本/API 发生变化时，测试可能揭示兼容性差异。锁定依赖提高可复现性，但不保证依赖安全、系统库完全相同或构建必然逐字节一致。

## 边界：严格锁定减少环境漂移

严格锁定减少环境漂移，也需要维护升级、安全补丁与平台适配；不能因为“可重复”就永远不更新依赖。

**跨语言迁移时，** Python pyproject/锁文件工具、Java Gradle/Maven、CMake/Conan/vcpkg、Rust Cargo、Go modules、Zig build system 都在组织源码、依赖和工具链，规则不同但目标相近。
