# 第 04 章：为什么要把计算过程变成函数？

同样的订单求和规则现在被后台列表页、报表页和结算页使用。复制三份循环虽能工作，但修复一个规则就可能漏改另外两份。

## 在单个脚本里

在单个脚本里，直接顺序写循环最容易理解。没有重复使用要求时，为它抽象出多个层次没有好处。

**教学实现：**

```python
amounts = [100, 250, -30]
total = 0
for a in amounts:
    if a >= 0: total += a
print(total)
```

## 报表结果 100

报表结果 `100`，结算结果 `70`。两个页面的输入完全相同，输出却不同，因为规则的复制件产生了偏差；这比“代码有点长”更具体。

**用于触发限制的代码／输入（实验场景，不伪称来自框架）：**

```python
# 两个页面各复制一份规则
report = sum(x for x in [100, -30] if x >= 0)
checkout = sum([100, -30])  # 漏掉了退款过滤，得到 70
```

**因此需要的能力。** 让规则只存在一个地方，其他模块以清楚的输入与输出约定调用它。函数是封装一段计算行为的最小工具。

## 把新机制落实成代码

**改进后的教学实现：**

```python
def sales_total(amounts: list[int]) -> int:
    result = 0
    for amount in amounts:
        if amount >= 0: result += amount
    return result

print(sales_total([100, -30]))  # 100
```

`amounts` 是调用时传入的数据；`result` 属于当前调用的局部计算；`return` 将结果交给调用方。调用者不必复制循环，而且未来改规则时只改此函数。

## 调用 sales_total([100,-30]) 时建立一个新的

调用 `sales_total([100,-30])` 时建立一个新的函数调用上下文，把输入绑定到 `amounts`，执行两轮，返回 `100`；函数局部的 `result` 名字在调用完成后不再作为该调用的局部绑定被使用。返回的是一个值，不是让调用方自动获得函数的所有内部状态。

## C 需要显式描述数组起点与元素数量

C 需要显式描述数组起点与元素数量，这是参数约定的差别。

**C 示例（教学代码，非所引用仓库的源码节选）：**

```c
#include <stddef.h>
#include <stdint.h>
int64_t sales_total(const int64_t *xs, size_t n) {
    int64_t out = 0;
    for (size_t i = 0; i < n; ++i)
        if (xs[i] >= 0) out += xs[i];
    return out;
}
```

C 的 `xs` 单独并不知道数组有几个元素，调用方必须正确传入 `n`；Python 列表自带长度与迭代协议。函数都是输入到输出的约定，但类型与安全保障不同。

## 函数调用并不是文本粘贴

订单报表和结账页面都要计算总额。复制循环会导致“一个入口忽略退款，另一个忘记忽略”这样的分歧。函数把一段计算变成由参数指定输入的独立过程：

```python
def total_valid(amounts):
    acc = 0
    for cents in amounts:
        if cents >= 0:
            acc += cents
    return acc

assert total_valid([100, -30, 250]) == 350
assert total_valid([]) == 0
```

调用 `total_valid([100, -30, 250])` 时，实参对象被关联给形参 `amounts`；局部名字 `acc` 只用于这次调用；遇到 `return` 后把结果交还调用处。重点不是把循环缩短成一行，而是建立明确的输入、输出边界。

```python
def bad_total(amounts):
    amounts.append(999)
    return sum(amounts)

xs = [100]
bad_total(xs)
assert xs == [100, 999]
```

这个反例说明：有返回值不等于纯函数。函数还可能通过共享对象修改调用者状态。接口签名只告诉我们一部分行为；对于资源所有权、副作用和异常，需要更明确的约定。到后面的章节，Rust 的借用与 Java/Python 的对象引用就会提供不同的约束方式。

## 对照规范和真实实现

**源码/规范阅读路线（供读者核对，并非声称已经逐行验证）：** [Python 3.13 函数定义与调用规则](https://docs.python.org/3.13/reference/)。

在语言参考中核对函数定义、参数绑定和返回语义；如果想继续深入 CPython，可从 `Python/bytecodes.c` 的调用相关指令出发，但不要直接假定“函数=固定的一段栈内存”。

## 实验：在 sales_total 前后打印同名变量 re

在 `sales_total` 前后打印同名变量 `result`；再连续调用三次：空列表、普通列表和混合列表，观察每次结果是否互相污染。

**应当观察到（自行运行前属于预期）：** 每次调用创建独立的局部绑定，空列表返回 `0`；若没有读写全局状态，多次调用不会共享 `result`。

## 边界：函数解决规则复用

函数解决规则复用，不自动实现输入验证、事务或并发安全。函数太碎也会增加阅读跳转成本；抽象应服从稳定的职责边界。

**跨语言迁移时，** 七门语言都有函数或等价可调用机制，但参数传递细节、泛型能力、错误处理、闭包捕获与调用约定并不相同。
