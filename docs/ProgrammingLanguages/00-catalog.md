# 从计算本质到语言实现：贯通 Python、Java、C、C++、Rust、Zig、Go

> **完整课程目录 · 10 篇 · 70 章 · 一条渐进式主线**

这套教程的目标不是分别学习七门语言，而是从一个最简单的程序出发，逐步推导出现代编程语言中的核心抽象，最终理解这些抽象在真实源码、运行时和硬件中如何实现。

全程固定一个不断演化的案例：**订单处理系统**。

它从一个求和函数开始，逐渐需要表达复杂数据、组织不同职责、管理资源、并发运行、连接外部系统，最终发展成可扩展的真实应用。

每章都遵循：旧方案能解决什么 → 遇到什么具体问题 → 为什么需要新机制 → 最小实现 → 对照真实源码 → 观察执行结果。

## 整个系列的三条分析线索

虽然分成十篇，但每章都应尽量连接以下三个视角：

- **语义线：它解决了什么问题？** 变量、函数、类、接口、泛型、所有权等抽象的必要性和行为约束。
- **实现线：它在底层怎样工作？** 数据表示、内存布局、编译器、虚拟机、调用约定、机器指令和运行时。
- **设计线：什么时候值得使用它？** 封装、组合、接口、继承、依赖注入、设计模式与架构的适用范围和复杂性成本。

比如研究接口时，先从「多种计价方式如何替换」引出接口的语义；到第六篇再追踪接口调用在真实运行时如何分派；到第九篇才分析接口是否真的降低了业务模块间的耦合。

这样同一个概念会随理解能力逐层深入，而不是第一次见到就把全部知识塞进去。

## 阅读与源码安排

整个课程应遵守三项固定约束：

**第一，每章只推动一个主要矛盾。** 一个知识点没有被真实问题逼出来，就不提前解释。

**第二，每个机制至少有一个最小实验。** 能运行则展示真实输入、执行与结果；源码分析固定版本或 Commit，严格区分源码节选、教学化简和伪代码。

**第三，七门语言是对照样本，而不是七套平行课程。** 不强迫每章都讲七遍。先使用最适合建立直觉的语言，再用其他语言解释真正不同的设计选择。

这 70 章形成的核心演化关系是：

```text
计算 → 状态与控制 → 数据建模 → 对象与组合 → 接口与多态 → 类型约束
     → 内存与生命周期 → 编译与执行 → 操作系统 → 并发 → 架构与工程取舍
```

最终希望达到的能力是：看到任何一段 Python、Java、C、C++、Rust、Zig 或 Go 源码，都能同时从计算语义、语言抽象、底层实现和工程设计四个角度解释它为什么这样写、怎样运行，以及还有哪些替代方案。
