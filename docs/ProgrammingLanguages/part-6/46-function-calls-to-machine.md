# 第 46 章：高级语言中的函数调用如何落到机器上？

我们已经能把加法变成机器指令，但调用 `discount(amount)` 时，CPU 怎样知道参数在哪儿，结果放在哪儿，函数结束后回到哪里？

## 从 C 代码看只有两次函数定义和一次调用

从 C 代码看只有两次函数定义和一次调用，完全不需要手写寄存器。但机器调用必须约定参数、返回和控制转移位置。

**教学实现：**

```c
long discount(long x) {
    return x * 90 / 100;
}
long checkout(long x) {
    return discount(x);
}
```

## 如果模块分别编译

如果模块分别编译，却没有共同调用约定，就会在调用边界解释错误的值。函数语义无法只靠“跳到地址然后回来”完成。

**用于触发限制的代码／输入（实验场景，不伪称来自框架）：**

```text
假设调用方把 x 放在寄存器 R1，
被调用函数却从 R2 读取。
双方即使“都支持 long”，结果也不可靠。
```

**因此需要的能力。** 定义调用约定（calling convention）与 ABI：参数和返回值位置、需保存的寄存器、栈对齐、符号等具体机器层协议。

## 把新机制落实成代码

**改进后的教学实现：**

```bash
# 在 Linux x86-64 上示意：
# gcc -O0 -S order.c -o order.s
# 然后阅读 checkout / discount 对应的汇编
# 真实寄存器与指令以机器、ABI、编译选项为准
```

这里不伪造固定汇编输出，因为优化器可能把调用内联，平台 ABI 也会改变参数位置。我们明确实验条件，再观察实际结果。

## 一次常规调用需要

一次常规调用需要：调用方准备实参、转移控制、被调函数读取参数并计算、放置返回值、恢复控制与必要的现场。调用约定使分别编译的代码能合作。

## Rust 的 extern "C" 可请求使用 C ABI

Rust 的 `extern "C"` 可请求使用 C ABI，但并不自动保证任意 Rust 类型都适合 FFI。

**Rust 示例（教学代码，非所引用仓库的源码节选）：**

```rust
#[no_mangle]
pub extern "C" fn discount(x: i64) -> i64 {
    x * 90 / 100
}
```

此示例用于解释调用约定意图；导出属性随 Rust edition/版本可能有额外安全属性要求，需要按相应版本验证。FFI 还必须考虑布局与生命周期。

## 一个调用为什么必须知道如何返回

`checkout()` 调用 `total()`，`total()` 又调用 `discount()`。每次调用都必须知道参数在哪里、返回值交给谁、调用结束后从哪里继续。最简单的执行器可以把“返回位置、局部变量环境”压入一份调用记录；嵌套返回时按后进先出顺序恢复。

在机器级程序中，寄存器和栈空间如何分工，通常遵循目标平台的调用约定（ABI）。例如参数可能优先经寄存器传递，超出限制的部分再使用栈；不能把“所有函数参数都在栈上”当作通用规律。

```c
long total(long a, long b) { return a + b; }
long checkout(void) { return total(100, 250); }
```

把这段 C 用 `-O0` 和 `-O2` 分别编译观察汇编，优化器可能直接常量折叠或内联，使你看不到预想的实际调用；这不是调用语义消失，而是优化改变了实现路线。

同样的函数语义在 Java 字节码、CPython 帧、Rust 机器代码中可能体现为不同结构。源码阅读应分别记录**谁保存返回信息、谁管理局部值、谁恢复执行位置**。

**源码/规范阅读路线（供读者核对，并非声称已经逐行验证）：** [GCC 文档：汇编输出选项 / 调用约定背景](https://gcc.gnu.org/onlinedocs/)。

结合平台 ABI 文档与编译器输出，不要把所有 CPU 都说成同样的六个参数寄存器。先看一个函数调用，再增加递归、异常和优化。

## 实验：在本机对简单 C 程序分别使用 -O0、-O2 -

在本机对简单 C 程序分别使用 `-O0`、`-O2 -fno-inline` 输出汇编，比较栈帧和参数传递细节。

**应当观察到（自行运行前属于预期）：** 不同优化设置可能生成不同指令与栈布局，但函数必须保持规定的可观察计算结果。

## 边界：ABI 让二进制互操作成为可能

ABI 让二进制互操作成为可能，同时限制了某些实现自由；语言内部调用未必总使用公共 C ABI。

**跨语言迁移时，** Java/JVM 和 CPython 可以借助虚拟机内部调用机制，C/C++/Rust/Zig/Go 在本机码边界需要各自遵守目标环境协议，不能无条件把它们等同。
