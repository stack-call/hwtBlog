# 第 48 章：编译器为什么能够改变程序的执行方式？

订单循环每次都计算固定的 `90 * 100`，浪费重复操作。编译器能不能把固定计算移到循环外，甚至在构建时算出来？

## 这段 C 在满足整数范围与指针有效性约束时语义清楚

这段 C 在满足整数范围与指针有效性约束时语义清楚。是否真的为每个元素执行常量乘法，不能仅凭源代码判断，取决于编译器优化。

**教学实现：**

```c
long sum(long *xs, long n) {
    long out = 0;
    for (long i = 0; i < n; ++i)
        out += xs[i] * (90 * 100);
    return out;
}
```

## 常量的值在编译期已知

常量的值在编译期已知，重复计算没有贡献新信息。我们希望编译器改变步骤而保持可观察结果。

**用于触发限制的代码／输入（实验场景，不伪称来自框架）：**

```text
假设 n = 1,000,000，
若每轮重新计算常量 90*100，
会出现大量与输入无关的重复工作。
```

**因此需要的能力。** 允许编译器在语义保持前提下做常量折叠、循环优化、内联等转换。优化是对实现执行方式的改变，不是让程序“随便算个差不多的结果”。

## 把新机制落实成代码

**改进后的教学实现：**

```c
long sum(long *xs, long n) {
    long out = 0;
    for (long i = 0; i < n; ++i)
        out += xs[i] * 9000L;
    return out;
}
```

我们手工把常量表达式折叠成 9000，表达了编译器可能完成的最简单优化。真实编译器能否与怎样变换取决于整数溢出规则、目标架构和优化策略。

## 未优化概念路径

未优化概念路径：加载 xs[i]、计算常量 90×100、相乘、累加；优化后常量计算移到编译期，运行时直接使用 9000。输入输出的数学关系未变。

## Python 的字节码编译器也可进行某些编译期简化

Python 的字节码编译器也可进行某些编译期简化，但不必等同于 C 的机器优化。

**Python 示例（教学代码，非所引用仓库的源码节选）：**

```python
import dis
def f(x): return x + (90 * 100)
dis.dis(f)
```

用本机版本的字节码观察常量是否被预先折叠；Python 的整数语义和 C 的固定宽度有符号溢出行为不同，因此优化合法性条件也不同。

## 为什么删除一行计算不等于改变程序

订单总额算完后有个无用变量：

```c
long total(long a, long b) {
    long unused = a * 7;
    return a + b;
}
```

在满足语言语义的条件下，优化器可以删除 `unused` 的计算，因为它对可观察结果没有贡献。但如果计算包含可观察副作用、易触发未定义行为或必须保留的异常语义，删除与重排就不能随意进行。

优化依赖的不是“看起来多余”，而是编译器对数据流、控制流和语言规则的证明。不同语言对整数溢出、异常与内存访问的约束不同，会影响允许的优化。

拿同样的程序比较 `-O0` 与 `-O2` 汇编；再将 `unused` 的值写入一个可观察输出，观察指令是否保留。不要以单次性能测试证明“某语言一定更快”：编译器版本、目标架构和输入范围都会影响结果。

本章的真正结论是：**保持语义不变**是优化的前提，而语义越精确，编译器可能获得的推理空间也越明确。

## 对照规范和真实实现

**源码/规范阅读路线（供读者核对，并非声称已经逐行验证）：** [LLVM 优化器源码与 Passes 文档入口](https://github.com/llvm/llvm-project)。

查看 LLVM 关于常量折叠、内联或 DCE 的固定版本资料，并在本机导出 IR/汇编作验证。优化实现涉及大量 pass，不需要在这章一次讲完。

## 实验：用 gcc -O0 -S 与 gcc -O2 -S

用 `gcc -O0 -S` 与 `gcc -O2 -S` 编译代码，对比是否保留常量表达式、是否变成移位或其他指令；记录工具链版本。

**应当观察到（自行运行前属于预期）：** 优化后汇编可能显著不同，但你不能在看输出前虚构它恰好用了哪条指令。整数溢出等边界必须以语言语义解释。

## 边界：优化通常改善性能

优化通常改善性能，却可能让调试与性能归因变复杂。并非所有手写“更短”的代码都更快，也并非所有自动优化都适合所有输入。

**跨语言迁移时，** C/C++、Rust、Zig、Go、Java JIT、CPython 特化等都存在优化机制，差别在优化时间、可用信息和必须遵守的语言语义。
