# 第 41 章：为什么计算机不能直接执行高级语言文本？

我们会写 `total = 100 + 250`，但运行时首先看到的是一段字符。它怎么知道空格、名字、加号与括号代表什么结构？

## 把源代码作为文本储存十分方便

把源代码作为文本储存十分方便，可以编辑、复制、版本控制。但一段字符串并不会自动形成可执行的计算结构。

**教学实现：**

```python
source = "total = 100 + 250"
print(source)  # 这里只是一段字符串
```

## 程序必须区分 token、成对括号、表达式优先级和赋值结构

程序必须区分 token、成对括号、表达式优先级和赋值结构。直接从左到右读字符会将 `100 + 250 * 2` 错读成 `(100 + 250) * 2`。

**用于触发限制的代码／输入（实验场景，不伪称来自框架）：**

```python
source = "total = (100 + 250"  # 少一个右括号
# 不解析就无法判断它究竟是哪种表达式
```

**因此需要的能力。** 先把字符划为有意义的单元，再根据语法规则形成结构树。词法分析与语法分析最终得到的 AST 表示“哪些操作嵌套在另一些操作内部”。

## 把新机制落实成代码

**改进后的教学实现：**

```python
import ast
source = "total = 100 + 250 * 2"
tree = ast.parse(source)
print(ast.dump(tree, indent=2))
```

Python 标准库 `ast.parse` 可将源码解析成树；你能在结果中看到 Assign、BinOp、Add、Mult 等节点。这个 AST 不是 CPU 指令，也还没有执行业务逻辑。

## 先识别名字 total、等号、整数与运算符

先识别名字 `total`、等号、整数与运算符；语法规则令 `250 * 2` 成为加法右操作数的子树；赋值节点将整个表达式挂到目标 `total`。树结构保留优先级。

## Go 的编译器也必须识别语法

Go 的编译器也必须识别语法，标准库还提供 parser 供程序分析。

**Go 示例（教学代码，非所引用仓库的源码节选）：**

```go
// 教学入口示意，需导入 go/parser, go/token
fset := token.NewFileSet()
node, err := parser.ParseFile(fset, "order.go", "package p\nvar x = 1+2", 0)
_ = node
_ = err
```

Go AST 与 Python AST 的节点类型和语言语法不同，但都把文本转换为有结构的数据。这里 Go 片段需要配合导入放进函数运行。

## 先让一段文本出现歧义

`100 + 250 * 2` 是字符串，但我们希望乘法优先。直接按空格切成词，再从左到右计算会得到错误结果 700，而遵守优先级应得 600。于是解析器必须构造带层次的结构：

```text
Add(
  Integer(100),
  Multiply(Integer(250), Integer(2))
)
```

这棵树就是一种 AST（抽象语法树）表示。它不是唯一可能的 AST，也不是机器指令；只是把文本中的语法关系变成更明确的结构。

可以编写一个只认识 `INTEGER + INTEGER` 的最小解析器，然后给它 `1 + 2 * 3`，让失败迫使引入运算符优先级。接着再添加括号，确认 `(1 + 2) * 3` 改变的是树的结构，而不是运算符的含义。

在 CPython 中，可以从 `Parser/` 与 `Python/ast.c` 附近研究语法和 AST 构造路径，但具体实现应固定版本。C、Java、Rust、Go、Zig 编译器都会以各自形式进行语法分析，不等于都使用完全一致的 AST 节点集合。

## 对照规范和真实实现

**源码/规范阅读路线（供读者核对，并非声称已经逐行验证）：** [CPython v3.13.5 `Parser/` 目录与 AST 相关源码](https://github.com/python/cpython/tree/v3.13.5)。

固定版本从 CPython `Grammar/python.gram` 与 `Parser/` 开始读，先核对表达式优先级、括号与赋值解析；不要一上来跳到优化器内部。

## 实验：对 1 + 2 * 3 和 (1 + 2) * 3

对 `1 + 2 * 3` 和 `(1 + 2) * 3` 分别调用 `ast.dump`，对比树中顶层运算节点，预测实际执行结果。

**应当观察到（自行运行前属于预期）：** 前者顶层是加法并以乘法为子树，值 7；后者顶层是乘法，值 9。树形状记录了语法优先级。

## 边界：AST 让语法明确

AST 让语法明确，也不是全部语义：例如 `unknown_name + 1` 可能语法完全正确，但名字解析或运行时会失败。

**跨语言迁移时，** Python/Java/C/C++/Rust/Zig/Go 都需要某种语法解析，具体语法树和编译前端实现不同。共同问题是“字符怎样变成结构”。
