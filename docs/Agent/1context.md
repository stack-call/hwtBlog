# 上下文管理

> 本节写作提示（写完请删掉所有 `>` 引用块）
>
> 开头用两三句话交代这一节要回答的问题。例如：上下文窗口是 Agent 最稀缺的资源，本节讨论如何决定"什么该进上下文、什么该被丢掉"。

## 为什么上下文是瓶颈

> 从三个角度展开，每个角度最好配一个能自己验证的现象：
>
> 1. **硬上限**：窗口有 token 上限，超了直接报错
> 2. **成本**：输入 token 通常按量计费，长上下文让每轮成本线性上升
> 3. **效果衰减**：信息越多，模型对其中某一条的利用率反而可能下降

## 上下文里都有什么

> 拆解一个典型请求的构成，说明每一部分谁在控制、能不能压缩：
>
> - system prompt（自己写，可控）
> - 工具定义 / schema（框架生成，往往比想象中占得多）
> - 对话历史（增长最快）
> - 检索结果（外部注入）
> - 工具返回值（外部注入，最容易失控，比如一次 `cat` 吐出整个文件）

## 权衡与陷阱

> 记录实际踩过的坑。例如：摘要会丢失细节且不可逆；截断可能砍掉任务开头给出的约束；
> 缓存能省钱但会锁定前缀，导致改动 system prompt 就全部失效。
